| U1 | **Writer API pulls one service at a time.** The intrusion-log demultiplexer pushes three types from one pass, so the writer either deadlocks or buffers everything. | qual, arch, sec | **Push session**: `ChunkedScanWriter.begin(scan) → append(service, source, capturedAt, chunk) → finish()`. It keeps a next-ordinal and `OccurrenceCounter` per service. `ServiceRecords` is a convenience wrapper over the session. A deterministic streaming test checks that chunk *k* commits before record *(k+1)·5000+1* is pulled. That test runs in `test`; the low-heap run is a CI smoke step. |
| U2 | **IN_PROGRESS isn't invisible.** Per-chunk alert upserts surface mid-import and orphan on failure. Unfiltered fact reads (Timeline, history, diff, sums) show uncommitted imports. Each chunk triggers about 90 invalidations of every pager. | arch, qual, sec | Chunks write `scan_finding.alertKey` only. **Alerts are created set-based in the final transaction** (`INSERT OR IGNORE INTO alert … SELECT … FROM scan_finding WHERE scanId=?`, then attach). Every fact-reading query requires an observation whose scan is `COMPLETE`; a SQL source gate enforces it. Pagers observe `ScanResult`, `forensic_timeline` and `alert`, not store tables. The failure path runs `NonCancellable`. |
| U3 | **No column to link a fact to its source key.** `factKey` is a one-way hash, so live DNS ↔ `ioc_match` linking can't be expressed in SQL. Live DNS keys change between phases. Id-less intrusion records lose today's dedup. | arch, corr, qual | Add `telemetry_record.sourceKey` (h128 BLOB, indexed) in schema 19. Live DNS carries `dns:<id>` from Phase A (`DnsEventDao.insertAll` returns ids). Id-less intrusion records carry `"$type ? $eventTime"`; identity stays content-checked. |
| U4 | **`forensic_timeline.recordId` never written.** Nesting, double-binding prevention and the only interim pin all depend on it. | arch | Finding rows take `recordId` from the chunk's `factIdByOrdinal`, from Phase A. Gate: every triggered finding row on a stored service has a resolvable `recordId`. |
| U5 | **Closed correlation alerts swallow new chains**, e.g. {P1,D2} after {P1,D1} was closed. Members are stored as strings (unindexable), the cap keeps the oldest refs, there's no `groupKey` column, and lookback admits bug-report facts. | sec, arch, qual | Overlap-join **OPEN** alerts only. Overlap with a CLOSED alert opens a new alert unless the chain is a subset of the closed one's members. `alert_member(alertId, kind INT, refId LONG)`, indexed `(kind, refId)`, keeps the **newest** 1,000. `alert.groupKey`. Correlation `alertKey = h128(ruleId|groupKey|openingScanId|min member)`. Live lookback atoms are bounded to `≤ scanStart` and exclude every import source. |

Candidates are collected by keyset on the observation PK. |
| U8 | **Disk handling.** The live disk-full fallback loses later findings. Preflight trusts attacker-controlled ZIP sizes. "Import anyway" removes all protection, and cleanup needs space. | corr, qual, sec | Live scan on `SQLiteFullException`: the rest of the same pass switches to evaluate-only, findings are saved with `recordId = null`, `telemetryState = FAILED`, and the watermark doesn't advance. Test: ZIP headers under-report sizes → abort at the reserve. |
| U9 | **Interim phases A–C**: no sweep, but event rows still written; capped rows need full lists; findings top-K needs a full list; A–B rows duplicate facts after C; C4's allow-list misses three caps and `getAllScans`. | qual, corr, arch | `deletePriorIntrusionLogRows` (forensic rows only) is kept until C3. C3 deletes the three caps and their `BugReportScreen` uses, plus a one-time cleanup of legacy event rows for scans with `telemetryState ∈ {STORED, PARTIAL_RETENTION}` (pre-feature `NONE` scans keep theirs). `getAllScans` is allow-listed until D2. |
