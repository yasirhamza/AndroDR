## Background

- **#268** — nothing checks rule `detection:` field names against
  `logsource-taxonomy.yml`. A typo'd field passes every gate and the rule is
  dead on-device (`SigmaRuleEvaluator` reads `record[fieldName]` at :203 and
  every matcher null-guards to false, e.g. `matchEquals` at :300). Same class
  #225 closed for permission literals via `PermissionLiteralCrossCheckTest`.
- **#269** — gate-4 fixtures feed field values verbatim, so they are blind to
  how a field is *computed* (e.g. a fixture asserting
  `com.baidu.input → is_known_oem_app: false` would silently stay wrong for
  `com.baidu.input_mi`, which is category OEM in `known_good_apps.json`).

### Failure-polarity matrix (corrected at regate — direction-dependent, not a
simple fail-closed/fail-open pair)

| Defect | Positive selection | Negated (`not`) filter |
|---|---|---|
| Selection **dropped** by parser (name absent from parsed map, `?: false` at evaluator :314/:347-348) | rule DEAD | **OVER-FIRES** (`not false` = true) |
| Selection **emptied** (present, zero matchers, `.all{}` = true at :190-192) | **OVER-FIRES** | rule DEAD |
| Matcher with **empty/null value list** (`field: []` / `field:` — constant-false for every modifier, e.g. `.any{}` on empty at :237; EXCEPT standalone `\|all: []` which is vacuously TRUE at :291, and `\|re: []` where the parser drops the matcher at :247-249 → row-2 behavior) | rule DEAD (over-fires for `\|all`) | **OVER-FIRES** (dead for `\|all`) |

## Merge dance (safe ordering, per CLAUDE.md)

1. Rules-repo branch → PR → local sweep green + green `validate` check on
   the rules PR (live CI gate since 2026-07-03).
2. AndroDR branch: **submodule bumped to rules branch commit** + Part 2
   changes → PR (`Closes #268`, `Closes #269`).
3. AndroDR CI green (build-and-test is the real gate; `submodule-check`
   goes red mid-ordering by design).
4. Merge rules-repo PR → re-point AndroDR submodule at the rules main merge
   commit → update AndroDR PR → merge AndroDR PR.
5. File the 6 follow-up issues.

**Standing rule established by this plan (stated in CLAUDE.md via Part 2
item 5, and in the taxonomy header comment, Part 1 item 5):
`logsource-taxonomy.yml` edits follow this same submodule-bump-first
ordering.** After Part 1 the taxonomy is the primary gate's trust root;
without this rule a taxonomy edit reaches rules main (and, via the 12h
fetch, live validation of served rules) with no AndroDR gate having seen
it. This includes flipping a service `unwired → active` at wiring time —
that flip is itself a taxonomy edit governed by the rule.
